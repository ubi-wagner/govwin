## 3. THE FINDING: the regression estate has rotted against its own fixture

`scripts/run-branch-drives.sh` (new) runs all 27 branch drives in one command and prints one table.
Its first run: **9 passed, 18 failed.** Almost none of those 18 is a product defect.

A new harness's first output describes the HARNESS, so every failure was classified before anything
was reported. Three rot patterns, one root cause — **the database was rebuilt (task #1) and the
drive estate still pins the previous generation:**

**(a) Accounts that no longer exist — 6 drives.** `drive-rls-{app,admin,portal,pages}`, `drive-pin`,
`drive-p3-invite` target `eric@immobileyes.com`, `expert@beacon-labs.test`, `admin@acme-navy.test`
and others. **None of them is in the users table.** The fixture holds 14 accounts; these are not
among them.

**(b) A tenant that no longer exists.** `drive-bridge-buckets` and `drive-end-to-end`'s default both
target `lighthouse`. There is no such tenant.

**(c) Hardcoded entity ids whose rows were deleted.** `drive-spine-t1-section-todo` pins a proposal
and a section by uuid, commented *"TVSF-R45 draft (18 unlocked sections)"*. **Neither row exists.**

### Why this matters more than 18 red lines

**A drive that cannot log in still prints a verdict.** `drive-rls-app` failed authentication, got
401 on every request, and concluded:

```
❌ FAIL — a DENY-ALL surfaced (see 0-count rows)
```

That is a *security finding*, shaped exactly like a real one, produced by a script that never
authenticated. Anyone reading the summary would reasonably believe RLS had broken. Nothing in the
output distinguishes "the door is locked" from "I never knocked" — the same failure B83's write-up
records, now at estate scale.

A regression suite that fails this way is worse than one that does not run: it manufactures
confident, wrong conclusions in both directions.

### What was NOT a defect, after checking

- **`provisioning-cockpit`: 24 passed, 1 failed.** The failing check asserts `ready === true` on a
  fixture where all 13 required items have no template. The real predicate is stricter than the
  design summary — it also requires `itemsUndecided === 0 && volumesUndecided === 0`. Measured:
  `items_undecided = 13`. **`getBuildReadiness` is right; the drive asserts a simplified bar.**
- **`opp-scout`: 3 of 4 passed.** Its one failure ("+0 LLM calls") is contradicted by its own
  evidence — the agent record shows `rounds:2, tool_calls:2, 365 tokens, cost $0.0008`. A
  measurement problem in the check, not a dead agent.
- **`amendment`** needs a `<solicitationId>` argument the orchestrator did not pass. My bug.
- **`atomization`** hit `EIO: i/o error` with 24 GB free. Environmental.

### Fixed here

The fixture had **no in-flight build** — every proposal and every section on the box was locked, so
*the primary customer action, editing a section, could not be demonstrated at all*. `verify-db-crud`
had been reporting this as a note for some time. A real build was provisioned through the real
purchase path (`drive-buy-and-build`), giving the box 17 unlocked sections. That closed the
`verify-db-crud` note and unblocked the guide capture (§4).

## 5. Open, and each one is a decision rather than a bug

1. **`OnCmsContentRequested` has no domain emitter** — not in the frontend, pipeline or CRM. The
   agent roster says so outright: *"Admin-launched via LaunchContentClient; no automatic emitter
   (that stays post-V1)"*, and that client posts to the generic workflow launcher. It cannot be
   cleared by firing, because **the launcher is not evidence**: it emits the operator's overlay AS
   the payload, so checking it against an `input_map` compares typing to itself.
2. **The drive estate needs a fixture reconciliation** (§3). Either re-seed the accounts/tenants the
   drives name, or repoint the drives at what exists. Until then those 18 are uncovered, not passing.
3. **Voice-of-Proposal has never been exercised with a real value by a user** — `payload.voice` is
   present-but-null in every observed full-draft payload. The wire is proven (B84); demand is not.
4. **The visual reviewer's eyesight is still unproven** — the emulator cannot see images and returns
   `[]` by design. One pass with a live key closes it.

## Addendum — the cross-tenant rule, applied and enforced

Owner's ruling: *"Nothing reads or writes cross tenant. Ever. That's what the bridges are for.
Messaging back and forth and inward copy of data only."*

Swept the whole schema from the catalog for stored references from one tenant's row to another's.
**One violation class, and it was residue:** 303 of 303 `atom_lineage` edges, written in a single
minute on 2026-08-12 by the KEEP+COPY copy-forward *before* `createAtom` grew its same-tenant guard.
A live copy today produces zero. `atom_members` 0 of 600, `atom_tags` 0 of 6015, all 23 direct FK
paths clean.

Both halves of the rule are now enforced where app code cannot route around them:

| | |
|---|---|
| **write** | mig **208** — trigger on `atom_lineage`, refuses a cross-tenant edge **even as superuser** |
| **read** | mig **209** — force RLS + `tenant_isolation` on `atom_lineage` and `atom_members`, the two link tables mig 117 never covered |
| **standing** | `check-tenant-isolation-invariant.mjs`, run as a suite preflight alongside the RLS-posture check |

Two exclusions, both printed on every run rather than silent: **platform scope** (`tenant_id IS NULL`)
is the platform plane, not another tenant — my first pass used `IS DISTINCT FROM` and reported the
documented template bridge as a violation; and **a person is not tenant data**, because a human
legitimately spans tenants and `proposal_collaborators.user_id` is an external collaborator by design.

Verified after: cross-tenant reads return **0** under `govtech_app` with own-tenant reads still
returning rows (30 and 285 — isolation, not deny-all); four lenses green; invariant sweep clean.

# Addendum 2 — the guides, redone against the canvas

The two front-door guides were rewritten in full against the arc this sweep proves, with the canvas
documented properly for the first time. `docs/CUSTOMER_ONBOARDING_GUIDE.md` and
`docs/RFP_ADMIN_OPERATIONS_GUIDE.md`.

## What was missing, and why it was missing

The canvas is where a customer spends every hour they spend in this product, and the guide gave it
**one step and one screenshot**. Not from neglect: `capture-guides.mjs` was route-driven, and
**almost nothing in the canvas is a route.** Overlays, the scope ladder, the selection verbs, the
insert palette, the format drawer, the AI panel, the library panel, preview — every one of them is a
STATE you reach by acting. A pass that only navigates cannot see any of it.

So the harness grew an `act()` primitive: perform an interaction, **assert the surface actually
opened**, then shoot. Without the assertion, a shot of a panel that silently failed to open is a
picture of the page behind it, captioned as the panel — the same class of lie as a 200 standing in
for a render.

## The fixture could only illustrate one of the three canvas surfaces

`canvas.format` forks the editor three ways — fluid pages, slides, grid — and **every one of the 78
stored proposal sections, and both standalone documents, was `letter`.** Two of the three surfaces
existed only in code.

Fixed through the product's own paths, not by writing rows:

| Surface | How the pass now gets one |
|---|---|
| Fluid pages | The in-flight Navy Phase I build (17 unlocked sections) |
| **Slides** | The template gallery — which was **empty**, because the template bridge had never been run on this box. Seeded the 39-template catalog through `seed-template-masters.mts` (masters → bridge → fan-out to all 5 tenants), then instantiated a deck with **Use this template** |
| **Grid** | The blank **Workbook** preset, then five rows of a real budget typed **through the editor**, and Saved |

A useful thing fell out of the third one. There is no populated spreadsheet anywhere in the
catalog, and that is correct rather than a gap: **every agency cost form is a `letter` canvas
carrying spreadsheet-style table nodes**, because an agency cost form is a page, not a workbook. The
grid surface is reached through the Workbook preset. Both guides now say so.

## Five defects, found by looking at the pictures

Full write-ups in `docs/BUG_LOG_2026-08-19.md` B88–B92.

| | What | Product or harness |
|---|---|---|
| **B88** | The sheet editor **doubled the first character of every cell** — `DDirect labor`, `1184500`. The one branch of `handleCellKeyDown` missing `preventDefault()`; React flushes the discrete event synchronously, so the browser's default insertion lands in the just-focused input. | **Product** |
| **B89** | The compliance panel printed `Margins 0.5555555555555556" all` — an unrounded points→inches division, and an `all` that read only `margins.left` while the document's four sides differed. | **Product** |
| **B90** | **An error page shipped in the admin guide.** `/admin/documents/[documentId]` is object-storage-backed; the pass handed it a table id, got a red "Document not found", and **both harnesses scored it green** because each carried its own incomplete copy of "what a broken page looks like" and neither matched a bare `not found`. | **Harness** |
| **B91** | Once the matcher was complete, `verify-surfaces` went red on a tenant library route — because it had been binding **another tenant's** atom and calling the correct refusal a rendered page. | **Harness** |
| **B92** | `/admin/pipeline` threw a hydration error **once**; not reproduced in 18 loads including a pinned non-UTC browser timezone. Recorded as a lead. The timezone-less `toLocaleString` next to it was fixed on its own merits. | **Unknown / product** |

B90 is the one worth internalising. Two independent mistakes had to line up — a wrong binding I made
after reading the note that said not to, and a duplicated definition that had drifted — and the
result was a customer-facing document illustrated with an error screen. The fix is structural:
`scripts/lib/error-surface.mjs` is now the **single** definition of "this page is broken", imported
by both harnesses, and `act()` runs the same gate so an interaction that navigates into a broken
page fails rather than being rescued by a `prove` selector that happens to match.

**Red-first on both product fixes.** B88's red evidence is the pre-fix capture (`DDirect labor`) and
its assertion was tightened from a substring to `span:text-is("Direct labor")`, which the buggy
render fails. B89 has three unit cases, each verified failing against the previous expression.
