## B1 — The heartbeat did not supervise the pipeline worker · FIXED
**Where** `frontend/scripts/sandbox-heartbeat.sh`
**Proven** The loop checks Postgres, the emulated-Claude endpoint and the frontend. Nothing checks
:8080. The worker died repeatedly through the overnight session while every heartbeat line read
`srv=ok emu=ok db=ok`.
**Why it matters** The worker is the component that RUNS the workflows. A monitor that reports
healthy while the automation engine is dead is worse than no monitor: it actively argues against
the symptom you are seeing.
**Fix** Added `start_worker` + a `wrk=` field. Starts on the OWNER connection per
docs/RLS_CUTOVER.md ("pipeline = owner") — as `govtech_app` every workflow dies writing
`process_instances`.
**Class → sweep for** *supervised-set gaps*: any monitor/health/status surface that reports on a
subset of the things it implies it covers. Check `/admin/workflows` Live monitor, the Command
Center System lane, and the failed-workflow alert row.

## B2 — "Never double-starts" guard depended on a binary that is not installed · FIXED
**Where** `frontend/scripts/sandbox-heartbeat.sh`
**Proven** `command -v ss` → missing in this container. The guard was
`ss -ltn | grep -q ':3000'`, so it ALWAYS evaluated false; on any cycle where `/login` was not yet
200 the script fell through to `start_server`. A Next standalone boot takes several seconds, so a
restart reliably spawned a second server, which then fought for :3000.
**Why it matters** The file header states "never double-starts if something already owns :3000".
The code promised something it could not do, and the failure mode was silent contention rather
than an error.
**Fix** `port_busy()` — `fuser` (present) first, `ss` retained as a fallback for hosts that have it.
**Class → sweep for** *unavailable-dependency guards*: any shell/tooling path that branches on a
command's success where the command may be absent. `command -v` before use, or pick a probe that
is guaranteed present. Also the general shape: **a comment asserting a guarantee the code does not
implement.**

## B3 — The admin Workflow Map showed 29 of 34 workflows and called it complete · FIXED
**Where** `frontend/app/admin/workflows/workflow-shapes.ts` (consumed by `workflow-map.tsx`)
**Proven**
```
catalog entries: 29     ← grep -oE "workflowName: '[A-Za-z0-9]+'"
pipeline classes: 34    ← grep -c 'class .*(Workflow):' pipeline/src/workflows/*.py
missing: OnIngestPhaseRequested{Extract,Matrix,Review,Molds}, OnPortalStageReviewRequested
```
`workflow-map.tsx:247` computes `const total = WORKFLOW_SHAPES.length` and renders
`{total} workflows · discovery + build spines + platform`. The count is derived from the catalog
itself, so it is **self-consistently wrong** — it can never notice it is missing anything.
**Why it matters** The four Ingest Studio phases are the ENTIRE gated ingest spine: the path an
admin uses to bring a solicitation in. They were invisible on the map, and a live instance of one
had no shape for the monitor to overlay its step status onto. The file header asserted "kept 1:1
with the Python registry (29 templates, verified file:line)" — the assertion was the stale part.
**Fix** Added all five shapes with DAGs read from the Python (including the loop-generated
`refute_0..2` colour-team steps at COLOUR_TEAM_SLOTS=3 and the shared `advance_phase` tail).
Header and the "29 templates" section comment now state 34 with the command to re-derive it.
**Class → sweep for** *self-referential counts*: any UI that reports "N things" where N is
`someLocalArray.length` rather than a count of the real population. The number cannot fail; it
just quietly describes the wrong set. Also: **a comment claiming 1:1 fidelity with another
system** — that is a promise nothing enforces.

## B4 — The Workflow Map displayed a trigger the workflow does not listen to · FIXED
**Where** `frontend/app/admin/workflows/workflow-shapes.ts` — `OnSolicitationReviewRequested`
**Proven** Catalog said `finder:solicitation.triaged:end`; the class declares
`finder:solicitation.review_requested:single`. Systematic diff of all 34 catalog triggers against
the Python found exactly this one mismatch.
**Why it matters** PATTERN_AUDIT HIGH-1 re-pointed that workflow at the tool's event because only
that one fires from the workspace (the triage route's `solicitation.triaged` is the legacy twin).
The fix updated the workflow but not its mirrors — so the admin console showed the dead trigger,
and `tests/test_pod4_wiring.py` asserted it too (fixed separately, commit c12c41d5).
**Class → sweep for** *un-mirrored corrections*: when a fix re-points a contract, find every
MIRROR of it — tests, catalogs, docs, UI labels. One source of truth changed; the copies did not.
Two copies of this one were stale in different languages.

## B5 — The live sandbox DB was 18 migrations behind the tree · FIXED (environment)
**Proven** `_migration_history` held 175 rows, head `176_seed_program_guide_drafts.sql`; disk had
193 files. `information_schema.columns` had **no** `volume_required_items.character_limit`.
**Why it matters** Not a code defect — but every character-limit feature silently did nothing on
this box, and five tables migs 177–190 create did not exist. Any E2E run would have been testing a
schema 18 versions old while the code assumed head. Independently surfaced by the docs audit.
**Fix** Ran `db/migrations/migrate.mjs` against the live DB: 17 applied, now 192 rows at head
`193_character_limits.sql`; 110 → 115 tables; all three character-limit columns present.
**Class → sweep for** *code-vs-schema drift on a long-lived box*: the migration runner is only run
on demand, so a sandbox silently rots behind the tree. The heartbeat could assert head parity.

# Quality bar — measured from the hand-built reference

`MIRAGE_OSW26BZ04_DP013_Patent_Holiday_Technical_Volume.pdf` is the standard the generated volumes
are judged against. Measured, not estimated:

| Property | Reference | My last run | Gap |
|---|---|---|---|
| Pages | **10 of 10** (envelope filled) | ~7 | under-filled |
| Text characters | **36,701** | 19,298 | ~half density |
| Images | **44** across 5 pages (4·11·12·3·14) | **0** | absent entirely |
| Font faces | **9** — Times NR reg/bold/italic/bold-italic · Arial reg/bold/italic · Symbol · Wingdings | 1 | no inline variation |
| Page size | Letter 612×792 pt | same | ✓ |

**The rule this sets:** fill the envelope deliberately. A 10-page cap means ~9.9 pages; a
3,500-character cap means just under 3,500. Under-filling is a failure mode, not a safe default —
an evaluator reads a half-empty volume as a half-made proposal.

**Surface that must be exercised** (Word · PPT · XLS): images, captions, inline bold/italic runs,
section headings, page headers/footers, tables, charts, bullet glyphs.
