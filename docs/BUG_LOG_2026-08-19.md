## B1 — The heartbeat did not supervise the pipeline worker · FIXED
**Where** `frontend/scripts/sandbox-heartbeat.sh`

## B2 — "Never double-starts" guard depended on a binary that is not installed · FIXED
**Where** `frontend/scripts/sandbox-heartbeat.sh`
**Proven** `command -v ss` → missing in this container. The guard was
`ss -ltn | grep -q ':3000'`, so it ALWAYS evaluated false; on any cycle where `/login` was not yet
200 the script fell through to `start_server`. A Next standalone boot takes several seconds, so a
restart reliably spawned a second server, which then fought for :3000.
**Why it matters** The file header states "never double-starts if something already owns :3000".
The code promised something it could not do, and the failure mode was silent contention rather
than an error.
**Fix** `port_busy()` — `fuser` (present) first, `ss` retained as a fallback for hosts that have it.
**Class → sweep for** *unavailable-dependency guards*: any shell/tooling path that branches on a
command's success where the command may be absent. `command -v` before use, or pick a probe that
is guaranteed present. Also the general shape: **a comment asserting a guarantee the code does not
implement.**

# Quality bar — measured from the hand-built reference

`MIRAGE_OSW26BZ04_DP013_Patent_Holiday_Technical_Volume.pdf` is the standard the generated volumes
are judged against. Measured, not estimated:

| Property | Reference | My last run | Gap |
|---|---|---|---|
| Pages | **10 of 10** (envelope filled) | ~7 | under-filled |
| Text characters | **36,701** | 19,298 | ~half density |
| Images | **44** across 5 pages (4·11·12·3·14) | **0** | absent entirely |
| Font faces | **9** — Times NR reg/bold/italic/bold-italic · Arial reg/bold/italic · Symbol · Wingdings | 1 | no inline variation |
| Page size | Letter 612×792 pt | same | ✓ |

**The rule this sets:** fill the envelope deliberately. A 10-page cap means ~9.9 pages; a
3,500-character cap means just under 3,500. Under-filling is a failure mode, not a safe default —
an evaluator reads a half-empty volume as a half-made proposal.

**Surface that must be exercised** (Word · PPT · XLS): images, captions, inline bold/italic runs,
section headings, page headers/footers, tables, charts, bullet glyphs.

## B6 — Six RLS tables seq-scan on the exact column their policy filters · FIXED (mig 194)
**Proven**
```sql
-- RLS-enabled + has tenant_id + no index whose leading column is tenant_id
purchases · agent_task_queue · notification_read_state ·
proposal_amendment_flags · shadow_admin_grants · vault_members
-- purchases' unindexed FKs: tenant_id, opportunity_id, proposal_id  (all three)
```
Each carries a `tenant_isolation` policy reading

tables are still small.
**Fix** mig 194 — the six policy-column indexes, purchases' other two FKs, and five
cascade/join-relevant FKs (`tenant_bucket_scores.bucket_id` is ON DELETE CASCADE and was scanning
the whole scores table per bucket delete). All `IF NOT EXISTS`. Gap query re-run after apply:
empty.
**Class → sweep for** *the index that should follow a policy*: whenever a table gains RLS on a
column, that column needs an index. Add it in the same migration that adds the policy.

**Where** `pipeline/src/workflows/processor.py:802` · every `handles_event` declaration

## B17 — Two "reviewed" verdicts asserted without evidence the reviewer ran · FIXED (2026-08-19)
**Where** `pipeline/src/workflows/actions/ingest_actions.py:136-148` ·
`portal_stage_actions.py:71-88` → `frontend/lib/portal-workflow.ts:511-533`
**Proven** `record_ingest_review` writes
`status='reviewed'`, `review={"resolution": …, "recorded_by": "advisory_manager"}` where
`recorded_by` is a **hardcoded string literal** and `resolution` comes from `payload.resolution`,
never from an agent result. The step is `ACTION` with `depends_on=None` — correct per the
hard-step-behind-AI invariant — so when the AI steps safe-skip (no key, rate-limited, fabric
absent) the draft is still stamped reviewed. `record_stage_review` is the same shape and its

**Class → sweep for** *provenance asserted by literal*: any `recorded_by` / `reviewed_by` /

## B30 — The engine records a safe-skipped step as "completed" · LOGGED (deliberately not fixed)
**Where** `pipeline/src/workflows/manager.py` (the `if step_result is not None:` branch) ·
every safe-skip return in `pipeline/src/workflows/processor.py`
**Proven** Live, through the real engine (`scripts/drive_b17_evidence.py`, RUN 1). With no fabric
the log says `AI_INVOKE action 'tool.advisory.reconcile' skipped (fabric=False, mapped=True)` and
the persisted record says:
```json
{"record": "completed", "review_manager": "completed"}
```
Every safe-skip returns `{"result": None, "skipped": True, "reason": …}` — a truthy dict — and the
manager writes "completed" for any step whose executor returned anything at all.
**Why it matters** Two live consequences. (1) It is what nearly defeated the B17 fix: any check
reading `step_status` cannot tell a step that worked from one that declined to. (2) The
`/admin/workflows` instance overlay reads the same map, so an operator watching a run sees a green
"completed" AI step that never called an agent — the monitor showing a healthy cohort in a
deployment with no API key.
**Why not fixed here** `depends_on` treats `'skipped'` as a reason to skip dependents. Writing the
honest status into `step_status` would cascade: `reconcile` (depends_on `refute_0`) would start
skipping whenever the refuters safe-skip, and the same shape repeats across the full-draft and
Studio workflows. That may well be the RIGHT behaviour — reconciling nothing is pointless — but it
is a semantics change to the engine with real blast radius, and it belongs in its own change with
its own drive, not inside a bug fix that had to ship correct today. B17 is closed without it:

## B24 — Retrieval never read the section's own words · FIXED

**Where** `frontend/lib/atoms.ts::selectForSection`, and the pipeline's mirror in
`pipeline/src/agents/archetypes/section_drafter.py::_search_library`.

**Proven** Four different technical sections of the Immobileyes T3CP volume — "Phase I Technical

## B37 — The standalone server cannot be found by name, so every "restart" was a no-op · FIXED (tooling)
**Where** `scripts/sandbox-up.sh` (and every ad-hoc restart line in this session).
**Proven** `pkill -f "standalone/server.js"` exits 0 having matched nothing; `pkill -f next-server`
matches the calling shell's own command line and kills the caller. Between them, three separate
"restarts" reported success while the original process kept serving. The cause: Node rewrites its
argv memory when it sets `process.title`, so seconds after boot `/proc/<pid>/cmdline` reads
`next-server (v15.5.14)` with no trace of the script path — a scan run immediately after `nohup`
finds the process and the same scan a minute later finds nothing, which reads exactly like "the
server died". Located it instead through the listening socket:
```
port 3000 inode=182580 → PID 18270
  cmdline: next-server (v15.5.14)
  cwd:     /home/user/govwin/frontend/.next/standalone
```
**Fix** Match on the working directory. `server.js` does `process.chdir(__dirname)`, so the
standalone server is exactly the process whose cwd is `.next/standalone`, and cwd is not rewritable
by the process the way argv is.
**Class → sweep for** *identifying a process by a string it controls*: a title, a name, an argv.
Anything self-reported can be rewritten. Prefer what the kernel owns — the cwd, the listening
socket, a pidfile you wrote yourself.

## B38 — The suite spent a full run on an app with no CSS · FIXED (tooling)
**Where** `scripts/sandbox-up.sh` — the standalone server was started without staging its assets.
**Proven** Measured the portal shell at a 390px viewport and printed every offender's ancestry:
```
aside.fixed inset-y-0 z-50 max-w-[85vw] …   x=8..382  pos=static ox=visible tf=none
nav.flex flex-col gap-1 text-sm             x=8..382  pos=static ox=visible tf=none
```
`pos=static` on a `fixed` element and a row-laid-out `flex-col` are impossible — unless no CSS
loaded. It hadn't: `/_next/static/css/cf149d9a1e580d24.css` → **404**, because `next build` does not
copy `public/` or `.next/static` into `.next/standalone`; you stage them yourself after every build,
and one `cp` in a restart line had been killed.
**Why it matters** With no Tailwind, `fixed`, `hidden`, `lg:` and `-translate-x-full` stop existing,
so the nav drawer renders inline at full width and `hitl-cc-mobile-audit` reports a 474px horizontal
overflow on **every tenant Command Center destination** — a convincing, specific, entirely fictional
layout regression. Once the stylesheet served, `scrollWidth` was 390 on the same pages: exactly the
viewport, zero overflow.
**Fix** `sandbox-up.sh` stages `public/` and `.next/static` unconditionally before starting, and the
verdict block now follows the stylesheet the login page actually links and fails the stack if it
does not return 200. No other probe in that script could see this: the server answers 200 on `/`,
renders every page, and runs every API route perfectly while completely undressed.
**Class → sweep for** *a health check that proves liveness instead of correctness*. "It returns 200"
is not "it works". For anything assembled from parts staged separately — static assets, a bundled
worker, a copied config — check the part, not the process.
