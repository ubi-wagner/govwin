## B1 — The heartbeat did not supervise the pipeline worker · FIXED
**Where** `frontend/scripts/sandbox-heartbeat.sh`
**Proven** The loop checks Postgres, the emulated-Claude endpoint and the frontend. Nothing checks
:8080. The worker died repeatedly through the overnight session while every heartbeat line read
`srv=ok emu=ok db=ok`.
**Why it matters** The worker is the component that RUNS the workflows. A monitor that reports
healthy while the automation engine is dead is worse than no monitor: it actively argues against
the symptom you are seeing.
**Fix** Added `start_worker` + a `wrk=` field. Starts on the OWNER connection per
docs/RLS_CUTOVER.md ("pipeline = owner") — as `govtech_app` every workflow dies writing
`process_instances`.
**Class → sweep for** *supervised-set gaps*: any monitor/health/status surface that reports on a
subset of the things it implies it covers. Check `/admin/workflows` Live monitor, the Command
Center System lane, and the failed-workflow alert row.

## B2 — "Never double-starts" guard depended on a binary that is not installed · FIXED
**Where** `frontend/scripts/sandbox-heartbeat.sh`
**Proven** `command -v ss` → missing in this container. The guard was
`ss -ltn | grep -q ':3000'`, so it ALWAYS evaluated false; on any cycle where `/login` was not yet
200 the script fell through to `start_server`. A Next standalone boot takes several seconds, so a
restart reliably spawned a second server, which then fought for :3000.
**Why it matters** The file header states "never double-starts if something already owns :3000".
The code promised something it could not do, and the failure mode was silent contention rather
than an error.
**Fix** `port_busy()` — `fuser` (present) first, `ss` retained as a fallback for hosts that have it.
**Class → sweep for** *unavailable-dependency guards*: any shell/tooling path that branches on a
command's success where the command may be absent. `command -v` before use, or pick a probe that
is guaranteed present. Also the general shape: **a comment asserting a guarantee the code does not
implement.**

# Quality bar — measured from the hand-built reference

`MIRAGE_OSW26BZ04_DP013_Patent_Holiday_Technical_Volume.pdf` is the standard the generated volumes
are judged against. Measured, not estimated:

| Property | Reference | My last run | Gap |
|---|---|---|---|
| Pages | **10 of 10** (envelope filled) | ~7 | under-filled |
| Text characters | **36,701** | 19,298 | ~half density |
| Images | **44** across 5 pages (4·11·12·3·14) | **0** | absent entirely |
| Font faces | **9** — Times NR reg/bold/italic/bold-italic · Arial reg/bold/italic · Symbol · Wingdings | 1 | no inline variation |
| Page size | Letter 612×792 pt | same | ✓ |

**The rule this sets:** fill the envelope deliberately. A 10-page cap means ~9.9 pages; a
3,500-character cap means just under 3,500. Under-filling is a failure mode, not a safe default —
an evaluator reads a half-empty volume as a half-made proposal.

**Surface that must be exercised** (Word · PPT · XLS): images, captions, inline bold/italic runs,
section headings, page headers/footers, tables, charts, bullet glyphs.

## B6 — Six RLS tables seq-scan on the exact column their policy filters · FIXED (mig 194)
**Proven**
```sql
-- RLS-enabled + has tenant_id + no index whose leading column is tenant_id
purchases · agent_task_queue · notification_read_state ·
proposal_amendment_flags · shadow_admin_grants · vault_members
-- purchases' unindexed FKs: tenant_id, opportunity_id, proposal_id  (all three)
```
Each carries a `tenant_isolation` policy reading
`tenant_id = current_setting('app.tenant_id')` in both USING and WITH CHECK. With no index the
policy is not a shortcut — it is extra work applied per row on a sequential scan.
**Why it matters** `purchases` grows monotonically with the business (a row per sale), is read on
every portal load to decide what the tenant owns, and had **none** of its three FKs indexed.
`agent_task_queue` is polled continuously by the fabric. Cheap to fix now precisely because the
tables are still small.
**Fix** mig 194 — the six policy-column indexes, purchases' other two FKs, and five
cascade/join-relevant FKs (`tenant_bucket_scores.bucket_id` is ON DELETE CASCADE and was scanning
the whole scores table per bucket delete). All `IF NOT EXISTS`. Gap query re-run after apply:
empty.
**Class → sweep for** *the index that should follow a policy*: whenever a table gains RLS on a
column, that column needs an index. Add it in the same migration that adds the policy.

**Where** `atoms/bulk/route.ts:81` (`atom_id`) · `scripts/drive-foundation-tvsf.mts:202`

## B9 — The archetype-fallback dispatch is dead for 32/36 agents, and double-fires the 33rd · FIXED
**Where** `pipeline/src/workflows/processor.py:802` · every `handles_event` declaration
**Proven** `processor.py` passes the bare `event_dict["type"]` to `fabric.has_handler`. Live DB:
```sql
select distinct namespace, type from system_events;
library | package.atomized      finder | solicitation.update_scan_requested
proposal | compliance.checked   identity | user.logged_in            …
```
`type` carries **no namespace prefix** — it is its own column. Yet `curation_qa` declares
`"finder.solicitation.triaged"`, `scoring_strategist` `"finder.scoring.completed"`,
`compliance_reviewer` `"proposal.section.drafted"` … 32 archetypes declare a string that can never
match. Only `librarian` registers the bare forms (`package.atomized`, `document.locked`), and no
workflow claims those — so it is the sole archetype the fallback actually reaches.
**Why it matters** The upload routes emit `library:package.atomized:single` **and** enqueue an
explicit librarian task. The `single` phase passes the `phase != 'start'` guard → the librarian ran
**twice per upload**, the second time off an event payload of `{filesProcessed, totalAtoms, source}`
— no cocoonId — producing the literal prompt `Catalog the atoms of package (cocoon) .` Both
`document.locked` emitters are payload-poor the same way. That contradicts
docs/AGENT_WORKFORCE.md:386 ("one task per package… enqueue is idempotent") and spends a tenant's
agent budget on a request that names nothing.
**Fix** A payload-aware second gate, `handles_dispatch(event)` on the base archetype (defaults to
`handles_event(type)`, so every other archetype is untouched); `fabric.handle_event` calls it;
`librarian` overrides it to require a cocoonId. **Deliberately NOT fixed** by prefixing the dispatch
key: that would wake ~32 dormant archetypes in one commit, against CLAUDE.md's "woken one at a
time". `test_agent_event_dispatch.py` now pins the bare-type contract so nobody "fixes" it that way
by accident.
**Class → sweep for** *a match on the wrong key shape*: any string compared across a boundary where
one side composes (`namespace:type`) and the other does not. It fails silently — no error, just a
handler that never runs. Also: **a capability whose only proof it works is that it was declared.**
