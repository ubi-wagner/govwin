## 8. The e2e run, and the trap that had been eating it

Three attempts at the full suite died before this one. Two to container restarts. The third I killed
myself, and that third one is the useful story.

**Symptom.** After every rebuild the served page 400'd on its own stylesheet:

```
login: 200
css  : /_next/static/css/948504a03b955a2f.css -> 400
```

The referenced hash did not exist in `.next/static/css/` (which held `2ac2dc0f…` and `85360ca7…`).
Running e2e against that produces failures that have nothing to do with the code under test — which
is why it was killed rather than reported.

**Cause.** A stale server was holding port 3000 and serving HTML from an older BUILD_ID, and it was
**invisible to every way I looked for it**:

```
ps aux | grep server.js      → nothing
ps aux | grep node           → only the emulator
pgrep -f standalone          → matched my own shell, not the server
ss -lptn 'sport = :3000'     → no rows
```

Next renames the process to `next-server (v15.5.14)`, so nothing containing `server.js`, `node` or
`next build` matches it. Found by going through the socket:

```sh
# port 3000 = 0x0BB8; state 0A = LISTEN
inode=$(awk 'NR>1 {split($2,a,":"); if (a[2]=="0BB8" && $4=="0A") print $10}' /proc/net/tcp)
for fd in /proc/[0-9]*/fd/*; do
  [ "$(readlink "$fd" 2>/dev/null)" = "socket:[$inode]" ] && echo "${fd#/proc/}" && break
done
#  →  5918 :: next-server (v15.5.14)
```

**Two rules out of this, both cheap:**

1. **Identify a server by the socket it holds, not by the string you expect in its command line.**
   A process can rename itself; the listening inode cannot lie.
2. **`pkill -f <pattern>` matches your own shell.** `pkill -f "standalone/server.js"` killed the
   bash process running it, because that string appears in its own command line — three times,
   returning exit 144 and leaving the target alive. Resolve to a PID first, then `kill` that.

**The gate that now precedes any e2e run** — cheap, and it would have caught all three attempts:

```sh
login=$(curl -s -o /dev/null -w '%{http_code}' http://localhost:3000/login)
css=$(curl -s http://localhost:3000/login | grep -oE '/_next/static/css/[^"]+\.css' | head -1)
csscode=$(curl -s -o /dev/null -w '%{http_code}' "http://localhost:3000$css")
[ "$login" = 200 ] && [ "$csscode" = 200 ] || exit 1   # serving UNSTYLED — do not test
```

`probe_frontend` already performs exactly this stylesheet check. It reported the failure correctly
every time; what was missing was treating its output as a gate rather than as information.

never written into a title — was invisible to that grep. **The same mistake shape as the negative
control earlier the same day: a check that did not touch what it claimed to cover.** Fixed by making
`probe_fixtures` derive the owner list from the call sites rather than keep a copy (`d4cededf`).

The 28 skips are the standing set — two T3CP specs whose source PDFs genuinely are not in this
checkout, and the rest gated on conditions this box does not meet. They skip with their reason
recorded, which is the contract from `docs/FIXTURE_INTEGRITY.md`.
