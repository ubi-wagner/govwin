# Sample Proposal — Aerivio Systems (fictional) → US Navy SBIR Phase I

A **100% complete, fully fictional** proposal built to exercise the RFP Pipeline
proposal engine end-to-end: multiple volumes, multiple artifacts per volume,
multiple canvas types, per-canvas draft→save→lock, the hierarchical lock/push
(section → artifact → volume → proposal), and export to every deliverable format.

**These are our canonical example outputs / templates** — point to them to show
what a finished proposal looks like across formats, and reuse the canvas JSON in
`canvas/` (see below) as starting templates.

- **Company (made up):** Aerivio Systems
- **Technology (made up):** quantized edge-AI acoustic threat classification for
  unmanned surface vessels
- **Solicitation (made up):** Navy SBIR Phase I, Topic N251-042, $150k / 6 months

> Everything here is fabricated for a functionality demonstration. No real
> company, person, agency record, or award is represented.

## The process that was run (RFP admin + shadow support)

Provisioned into the schema and driven through the real lifecycle:

```
provision  4 volumes · 5 artifacts · 7 canvases · compliance matrix seeded
  Volume 1 (Technical) ── artifact "Technical Volume" ── 3 canvases
  Volume 2 (Commercialization) ── 1 canvas
  Volume 3 (Cost) ── 1 canvas
  Volume 4 (Supporting Documents) ── 2 artifacts (Key Personnel, Facilities) ── 2 canvases
draft      each canvas drafted (AI-drafted content, then styled)
lock       Volume 1 locked canvas-by-canvas → artifact rolled up (is_locked)
push       "Lock Volume" hierarchical push for Volumes 2, 3, 4 → each rolled up
result     7/7 canvases · 5/5 artifacts · 7/7 matrix satisfied → proposal ADVANCE-READY
audit      section.locked×7 · artifact.locked×5 · document.locked×4 · proposal.advance_ready×1
```

Every lock — whether a single canvas or a hierarchical push — runs the identical
per-canvas stricture (`lib/proposal/lock-section.ts::lockSectionCore`): CAS lock,
`section.locked` event, compliance-matrix → satisfied, canvas snapshot, library
harvest, then the artifact / volume / proposal roll-ups. The hierarchical push
(`.../lock-scope`) simply loops that core, so "close + move" at any level is fully
audited per canvas.

## Regenerate

```bash
cd frontend
npx tsx scripts/gen-sample-proposal.mts   # writes the 6 files here
```

PDF export uses Chromium via Playwright (`PLAYWRIGHT_CHROMIUM_EXECUTABLE` or an
auto-detected `chromium-*` under `PLAYWRIGHT_BROWSERS_PATH`); the docx/pptx/xlsx
exporters are pure Node (no browser).
