# Sample Proposal — Aerivio Systems (fictional) → US Navy STTR Phase I

A second **100% complete, fully fictional** proposal, built to exercise the RFP
Pipeline engine on a **Navy STTR** — and, deliberately, to exercise the **atom
reuse loop** across pursuits: the same small business (Aerivio) as the AFWERX CSO
sample (`docs/sample-proposal/`), now teamed with a **Research Institution** as an
STTR requires, so its library carries and re-contextualizes pursuit-to-pursuit.

- **Small Business (prime, made up):** Aerivio Systems
- **Research Institution (made up):** Cascadia State University, Applied Ocean Acoustics Laboratory
- **Technology (made up):** propagation-aware, distributed **edge-AI acoustic
  classification** across a mesh of power-starved undersea nodes — an evolution of
  the AFWERX single-vessel classifier into a Navy distributed-sensing problem
- **Solicitation (made up):** US Navy STTR Phase I, Topic **N25B-T042**,
  "Distributed Edge Acoustic Sensing for Contested Undersea Environments"
- **Structure (as requested):** **18-month / $250,000 base** + **6-month / $150,000
  priced option** (total $400k / 24 mo)

> Everything here is fabricated for a functionality demonstration. No real company,
> university, person, agency record, or award is represented.

## What makes it an STTR (vs. the SBIR sample)

- **A Research Institution partner is mandatory.** Cascadia State (RI) contributes
  the ocean-acoustics research — channel characterization, propagation models, the
  range corpus — that Aerivio (SBC) cannot supply alone. New research collaborators
  (Dr. Okonkwo, RI Co-Investigator, + graduate researchers) appear in Key Personnel.
- **The statutory work-split is enforced and shown:** SBC ≥ 40%, RI ≥ 30%
  (realized at **SBC 56% / RI 35%** across base + option in the Cost Volume).
- **An Allocation of Rights Agreement** (SBC/RI IP) is described in the Technical
  Volume and the SOW's Data Management section.
- **Facilities & Equipment covers both parties** (Aerivio lab + Cascadia range/tank).

> **v2 section flow (canvas geometry redesign, Phase 1).** The Technical Volume, SOW,
> and deck are authored as **v2 CanvasDocuments** — an ordered `sections → groups → nodes`
> layer with layout intent (`flow` for documents, one section per slide). **No forced
> `page_break`s:** content runs continuously across page boundaries, so the
> bottom-of-page whitespace gaps are gone and the page count *emerges* (6 / 4, each
> within its compliance cap) rather than being padded to a target. Figures and tables
> are `keep_together` groups so a figure never splits from its caption. Measure it with
> `scripts/measure-canvas-flow.mts` (paginate() estimate + the real Chromium/pdfjs page
> count + a continuity check that flags any near-empty interior page). See
> `docs/CANVAS_GEOMETRY_REDESIGN.md` §5–9.

## The lifecycle + the reuse loop (emulated end-to-end)

`frontend/scripts/navy-sttr-e2e.mts` drives the full loop against the live schema
and, uniquely, demonstrates **cross-pursuit reuse**:

```
seed       Aerivio library carries 8 prior AFWERX atoms (context: agency:air_force, program:cso)
ingest     Navy STTR opportunity (agency:navy, program:sttr, topic N25B-T042)
matrix     11 Navy STTR required elements → proposal_compliance_matrix
skeleton   4 volumes (V2 Technical / V3 SOW / V4 Cost / V5 Supporting) · 4 artifacts · 11 molded sections
reuse-match  for each mold, the prior AFWERX atoms SURFACE by content-class (kind/vol) but score
             ctxMatch 1/3 against the Navy context → flagged RE-CONTEXT (agency/program differ);
             the STTR-only Research-Institution element is NET-NEW (no prior atom)
lock       each section → matrix advances to 11/11 SATISFIED
library    harvest 11 Navy atoms (context: navy/sttr) → library now spans 2 pursuits (8 + 11 = 19)
lineage    8 Navy atoms record atom_lineage(reused_from) → their AFWERX parent — the loop, with pedigree
export     V3/V4/V5 re-exported FROM the locked sections (round-trip sanity check)
```

This is the founder's "seminal atoms with context → reused with new context for the
Navy prop" made concrete: the reuse ranking (`ctxMatches` in `lib/atoms.ts`, over
`agency/program/phase/tech/dept`) is exactly what surfaces the AFWERX atoms and
exactly what flags them for re-context. Run: `node --import tsx scripts/navy-sttr-e2e.mts`.

## Regenerate

```bash
cd frontend
npx tsx scripts/gen-navy-sttr-proposal.mts   # writes the 6 files here + canvas/ templates
npx tsx scripts/measure-canvas-flow.mts      # paginate() estimate + real PDF page count + continuity check
node --import tsx scripts/navy-sttr-e2e.mts   # matrix + skeleton + reuse loop (needs DATABASE_URL)
```

PDF/pptx export uses Chromium via Playwright (auto-detected `chromium-*` under
`PLAYWRIGHT_BROWSERS_PATH`); the docx/xlsx exporters are pure Node.
